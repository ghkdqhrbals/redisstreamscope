Redis compatibility

Tested from Redis 6.2 through 8.8.

Version Status Details
6.2 CI tested Core Streams features, groups, pending entries, XCLAIM, and XAUTOCLAIM. Group lag and separate inactive time are not exposed by Redis.
7.0 CI tested Adds consumer-group lag and entries-read metrics.
7.2 · 7.4 CI tested Adds separate consumer inactive-time reporting. All current metrics are available.
8.0 · 8.2 · 8.4 · 8.6 · 8.8 CI tested All current StreamScope features and metrics are available.

Each pull request tests the latest patch release in every listed version line. A new Redis version is supported only after it passes this matrix.

Interface

Built for long-running operational work.

Quick start

Start first. Configure inside.

1

Start StreamScope

docker run -d --name streamscope -p 8080:8080 -v streamscope-data:/data ghcr.io/ghkdqhrbals/streamscope:latest
2

Sign in

http://localhost:8080 · admin / password

3

Connect Redis

Open Settings → Redis connections. Add your server, test it, and save. Standalone, Sentinel, Cluster, ACL, passwords, and TLS are all supported.

Docker Desktop host Redis Use host.docker.internal:6379 instead of localhost:6379 on macOS and Windows.

Configuration

Configure everything in the browser.

Persistent settings

Mount /data to retain application settings across container updates and restarts.

Redis connections

Add, test, reconfigure, or remove Redis connections from Settings. There is nothing to prepare before the container starts.

Container port

The internal port defaults to 8080. Map any host port with Docker, for example -p 9090:8080.
